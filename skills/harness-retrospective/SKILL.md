# Harness Retrospective

1. Start from outcome and validation evidence, not recollection alone.
2. Identify which Constitution rules, Skills, scripts, and validators changed the result.
3. Count necessary/unnecessary interruptions, repeated questions, manual relays, and blocking time.
4. Flag unused Skills, redundant artifacts, context conflicts, and missed defects.
5. Propose add, narrow, delete, or defer actions.
6. Promote a rule to Universal Core only after repeated cross-project evidence.

Use `templates/RETROSPECTIVE.md`. Deletion is a successful outcome when it reduces noise without weakening evidence.
