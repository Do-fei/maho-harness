# 架构

English: [`../en/ARCHITECTURE.md`](../en/ARCHITECTURE.md)

MAHO 将可移植工程规范与客户端专属发现路径分离。

```text
用户需求
    |
验收合同
    |
通用核心 -------- 技术栈规范包
    |                    |
项目宪法 ---------------+
    |
智能体 Skill 适配器
    |
直接验证 + 受保护路径快照
    |
完成证据
    |
必要时进行全新独立验收
```

## 通用核心

核心定义证据状态、授权边界、零覆盖初始化、命令验证和完成语义，不包含具体框架标识。

## 技术栈规范包

技术栈规范包由声明式元数据和指南组成。它们从有边界的仓库信号中提出检查和运行时探针。检测到技术栈不等于已经证明运行时行为。

## 项目宪法

项目宪法记录项目专属命令、受保护与生成路径、授权范围、所选技术栈规范包和所需证据。生成内容必须经维护者审阅后才算完整。

## 智能体适配器

适配器把一份规范 Skill 目录映射到不同客户端的发现目录。多个客户端读取 `.agents/skills`，MAHO 会去重共享目标。客户端专属目录只是薄副本，不是分叉实现。

## 证据边界

验证保存退出码、时间戳、字节数和哈希，不保存原始输出或原始参数数组。受保护路径快照受单文件大小、总字节、条目数、深度和耗时限制；超过限制时采用失败关闭。

## 非目标

MAHO 不替代客户端沙箱，不运行远程智能体，不选择模型，不管理凭据，不部署软件，也不会因为存在适配器就宣称已经提升成本或性能。
